# Skye π0.5 离线逻辑验证

最初按用户要求在现有工作区完成离线接口验证；随后用户授权开始在4090上位机分步部署。离线核心只依赖 Python 3.10+ 标准库，不加载 SDK、不连接机器人，也没有运动执行命令；`deploy/` 包含官方模型环境及Orin真实相机、被动SDK状态的远程推理链路，动作只记录。所有新增内容都在 `vla/`，现有 `skye_task/`、`tests/`、`config/` 保持原样。

2026-11-13部署结果：官方π0.5-DROID简短推理通过；4090策略服务及Orin相机服务已启动；5次真实观测远程请求通过，首次编译后四次平均85.82 ms。当前输出为DROID单臂15×8，夹爪缺失使用显式标注的诊断值，尚未接入Skye双臂执行。[部署与复跑说明](deploy/README.md)。

## 运行

在 `gento_skye` 根目录执行：

```bash
python3 -m unittest discover -s vla/tests -v
python3 -m vla demo --output /tmp/skye-vla-demo.json
python3 -m vla replay /tmp/skye-vla-demo.json

# 同时验证角度制和增量关节动作；使用新的输出文件名
python3 -m vla demo --joint-unit deg --arm-action-mode delta --output /tmp/skye-vla-deg-delta.json
```

输出文件已存在时拒绝覆盖。`demo` 使用三张不同颜色的合成 RGB 图、脚本生成的六步动作块和三轮理想反馈，每轮只规划前三步，然后重新观测；这不是 π0.5 推理，也不是机器人动力学仿真。日志包含无损压缩的原始 RGB、传感器时间戳、模型侧动作、示例限值和规划结果，`replay` 重新解码与校验，检测和原记录的差异。

2026-11-13 本地验证结果：新增23项测试通过；原 `tests/` 152项通过；`chassis/tests/` 20项通过、5项跳过。弧度/角度与绝对/增量的四种组合均完成三轮、每轮三步的离线规划和回放。检查时未连接机器人或4090上位机。运行产物位于被Git忽略的 `runs/vla-offline-20261113-s_kk2a5w/`，包含四份输入/动作日志及 `summary.json`。

## 数据约定

| 项目 | 当前约定 |
| --- | --- |
| 机器人状态和动作 | `[左臂7, 左夹爪, 右臂7, 右夹爪]`，共16维；全部为物理弧度 |
| 模型侧状态 | 同顺序；夹爪归一化到0～1，随后补零至32维 |
| 模型侧动作 | 输入本适配器的动作已完成反归一化；32维，读取前16维 |
| 关节单位 | 默认弧度；可显式选择角度制，仅转换14个臂关节，夹爪始终为0～1 |
| 动作语义 | 默认绝对目标；delta模式中，每个关节增量均相对本次观测，而非相对前一个预测；夹爪始终为绝对目标 |
| 夹爪标定 | 左右可分别配置；当前示例采用交接记录中的张开0 rad、闭合0.94 rad；越界拒绝，不静默裁剪 |
| 图像 | 三路已预处理的224×224 HWC RGB uint8，显式指定来源；不猜测四宫格位置 |
| 时钟 | 同一会话的monotonic纳秒；回放使用记录时钟，不与当前系统时钟混用 |
| 时效 | 默认最大年龄200 ms、传感器时间差50 ms，是待实测调整的逻辑参数；推理后再次校验 |
| 动作节奏 | 示例20 Hz、六步一块、规划前三步后重观测；不是推理频率或实测控制频率 |

相机源标识 `head_monocular`、`wrist_left`、`wrist_right` 只用于合成样例，不代表已发现的ROS话题。用户确认硬件为头部双目深度相机、头部单眼相机和左右腕广角相机；拟优先选头部单眼RGB及两腕RGB，最终选择仍需看真实视野与成像质量。额外头部/深度视图不强制输入模型。

`Adapter.inputs()` 中的图像是带原始字节和时间戳的 `RGBFrame`，数值是Python tuple，便于不安装numpy的离线测试。迁移后还需转为numpy数组，并接入自定义openpi输入/输出变换；它不是现成的WebSocket请求或可以直接传入官方模型的完整输入。

这里不执行模型归一化或反归一化。后续必须按Skye示教数据计算 `norm_stats`，由openpi策略变换链处理一次；delta变换也只能出现一次。若策略服务已输出16维绝对物理动作，应调整接入边界，不能再次补/裁维或叠加delta。角度制选项只验证关节单位转换，不代表兼容任意KMD checkpoint的夹爪及其他约定。

## 已覆盖与验证边界

离线检查包括左右臂/夹爪顺序、弧度与角度、夹爪量程、增量锚点、补维/裁维、相机来源、RGB形状、图像/状态同步、推理后过期、整块位置/速度/加速度检查、重规划节奏、无损日志和确定性回放。

动作块全部通过数值检查后才返回前缀；尾部越界也会拒绝整块。示例限值标为 `synthetic_demo_NOT_robot_limits`，不是现场标定。结果固定包含 `collision_checked: false`、`execution_supported: false`；数值检查成功不表示机器人可安全执行。

本地URDF虽然有碰撞网格，但 `Joint1_L` 的位置上下限和速度都为0，不能直接用于安全限位。尚未实现或验证双臂/机身/环境碰撞、连续轨迹插值、断网停止保持、SDK互斥、夹爪接触行为及真实闭环控制。
