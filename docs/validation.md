# 当前验证与关键限制

更新日期：2026-11-11。这里只保留当前有效结论，点位明细以[方案](../方案.md)及[默认配置](../config/default.json)为准。

## 已验证范围

用户已使用准备位 J1=±90°、接盘位 J1=±85° 跑通一轮整体流程。保留的 [runs/latest.json](../runs/latest.json) 为 `completed`，包含夹爪动作、升降 500→450→500 mm、前伸／下降、退出及回准备位。动作完成仍不等于检测到夹持或放置成功；`grasped`／`placed` 为未知，尚无完整任务成功率结论。

以太网 SDK 到双侧末端 CAN 的收发、使能、周期控制和失能反馈已验证。用户确认左右角度增大闭合、减小张开，并标定张开 0 rad、闭合 0.94 rad。独立测试及手动读取工具保留用于后续标定。

## 必须保留的约束

- **碰撞记录：**旧接盘位 J1=±29.327° 在准备→接盘 MoveJ 中出现双手碰撞，已从有效配置与内置默认值中移除。程序没有在线碰撞检测；更改点位后需重新验证完整路径，规划可达不代表路径无碰撞。
- **重复运行：**SDK 0407 仅接受 5–5000 个轨迹点。原先静止臂只发 2 点导致上传返回 `-19`；现改为静止臂 5 点，短规划轨迹保留路径并补终点，已有连续两轮离线回归覆盖。
- **逆解与连续性：**直线规划选择邻近当前关节的逆解，上传前校验首点。旧点位出现的工作空间错误说明单段可达不等于完整后续路径可达。
- **只读规划：**`plan-check` 从当前反馈计算后续双臂路径，要求升降已在 450 mm；不移动到接盘位、不验证升降执行、不发送控制或停止指令。
- **夹爪误差：**实测张开反馈曾偏离目标约 0.04–0.05 rad。当前到位容差 0.08 rad、稳定 0.1 s；保持容差 0.15 rad、连续超差 0.5 s 才失败。保留故障、非 On、反馈失联及动作超时检查，不以堵转判定夹持成功。
- **停止与退出：**整体任务失败不自动松爪或失能；退出后软件不再周期保持，物理使能状态不能据此推断。独立标定脚本会失能卸力。
- **连接与时基：**双臂与夹爪共用 SDK 连接，独立工具使用互斥锁；外部控制源仍需人工协调。轨迹时基默认 50 Hz，SDK 无实际频率查询接口，需按设备核对。

## 离线验证

```bash
python3 -m unittest discover -s tests -q
```

覆盖运动编排、两轮连续运行、轨迹点数、坐标转换、反馈到位、停止／超时、只读规划、夹爪协议、容差及共享连接。测试替身不连接真机，不能验证碰撞、夹持效果或导航精度。当前整理仅同步默认点位、精简文档和清理旧产物，未下发真机动作。
