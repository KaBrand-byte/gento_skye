## 2. 规划时延（要求：数据输入 → 规划完成 / 开始运动 < 1.2 s）

定义：**输入** = 激光快照拼好（6 帧，24 万点）或定位稳定；**规划完成** = 发出命令前；**开始运动** = 地图位姿变化 > 1 cm / 0.5°。切模式和解除驻车（每次约 0.8–1.3 s）在抓数据之前完成，不在区间内。

## 3. 结论与后续

- **启动时间满足要求**：四个任务的启动，输入 → 规划完成 25–152 ms，输入 → 开始运动 288–479 ms。
- **全程规划完成均 < 1.2 s**，但 D 站进场那一步余量小（1128 ms），按“开始运动”算超了 82 ms。可选的改进（结果不变的提速）：同一帧点云只去除一次机器人自身点（现在每个检查都重算，每次约 60 ms）、进场检查不重复做规划里已做过的平移检查。
- 复现：底盘上 `run.sh latency 5`（或 `gento latency 5`）生成同样的报告。
