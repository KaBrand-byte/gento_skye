本记录保留旧点位和 150 mm 位移下的实验结果。用户随后已更正示教位及位移；当前配置与验证见[更正后的离线验证](2026-11-11-corrected-poses.md)。

用户在 13:43–13:44 运行 `python3 -m skye_task run --config config/default.json`，设备报告 GentoSkye.V3.0_M6SC-696-V4.0，SDK 与控制器版本均为 `00040701`，有效自由度符合方案。

## 实验结果

| 阶段 | 结果 |
| --- | --- |
| 连接和位置模式 | 双臂、头、腰、升降均成功 |
| MoveJ 到准备位 | 程序到位检查通过，约 12.060 s |
| MoveJ 到接盘位 | 程序到位检查通过，约 12.055 s |
| 接盘位触发任务 | 正常 |
| 前伸 150 mm | 同步直线规划返回 `-1020`，没有上传或启动本段轨迹 |
| 停止 | 双臂停止返回掩码 `0x03`，没有继续下降或退出 |

原始错误为 `FX_InvKine_Pilot: Target is out of workspace, and Joint4 is near singularity`。`-1020` 本身是通用规划失败码；对应 SDK 源码在肩到腕心距离达到几何臂长上限时输出这条错误，不能仅凭其中的 “Joint4” 判定为当前 J4 已处于奇异位形。

实际读取的固定反馈为：腰 `[-0.004440, -0.001684]` °、头 `[-0.000645, -0.002012]` °、升降 `[499.832001]` mm。两臂控制器 `tool_kine` 均为六个零，即当前规划 TCP 为法兰参考点。

## 离线复现

使用本机原生 SDK `00040701`，从 SDK 自带 `CT040701/cfg_default_040701/GentoSkye-V3.0_M6SC-696-V4.0_00040701.ini` 读取模型，通过 `init_single_arm_manual()` 初始化后，用方案中接盘关节值计算。该复现未连接控制器；出厂模型可能与设备定制参数不同。

| 模型计算项 | 左臂 | 右臂 |
| --- | --- | --- |
| 接盘位法兰 XYZ（各臂基系，mm） | 413.811, 406.153, 254.768 | 485.619, -392.260, 215.956 |
| 保持姿态前伸时的几何极限（mm） | 116.382 | 54.488 |

几何极限按该 SDK 的肩到腕心上限约 602.079 mm 计算，只用于解释不可达，不能当作可直接执行的距离；它未包含关节限位、路径、碰撞和奇异位形余量。

原生 SDK 同步规划复现：

- 前伸 150 mm：复现同样的 `-1020` 和工作空间错误。
- 改为按当前关节选择邻近逆解后，前伸 25 mm、50 mm 可规划，分别生成 58、78 个双臂同步点；首点与参考关节最大偏差小于 0.00001°。
- 在上述 25 mm 或 50 mm 前伸之后继续下降 150 mm，仍返回 `-1020`。因此只缩短前伸距离不足以验证整条路径。

这说明当前接盘姿态与原定 150 mm 前伸、150 mm 下降的组合存在工作空间冲突。若继续采用这些位移，应重新示教留有足够前伸和下降余量的接盘位，并检查完整路径。

## 已修正的实现

原实现沿用厂商示例的 `ZSP_Type=1`、肘平面向量 `[0,0,-1]`，会施加额外肘平面约束。离线计算仅前伸 1 mm 时，其逆解与参考关节最大差值分别约 76.2°、47.2°。已改为 `ZSP_Type=0`，使用当前关节选择邻近解；同时在上传前校验轨迹首点，拒绝与当前关节不连续的轨迹。此修正不扩大工作空间，150 mm 原目标仍不可达。

已增加失败前的起始／目标位姿、关节参考与位移记录，以及 `plan-check` 命令。该命令只连接、读取反馈和模型并在本机规划当前姿态之后的前伸、下降、退出、回准备位；不切换模式、不下发保持位置、上传、运行或停止指令，默认结果为 `runs/plan-check.json`。

```bash
python3 -m skye_task plan-check --config config/default.json
```

当前工作环境尝试只读连接返回 `-2`（`ethernet work is down`），未取得新的设备反馈。以上定量复现均来自本地出厂模型。需在能连接设备的终端执行只读检查，以取得控制器实际模型下的起点和目标记录。新的代码尚未执行真机运动；44 项离线测试通过。
