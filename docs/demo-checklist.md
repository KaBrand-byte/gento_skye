# 演示当天检查单

厂家底盘已经出过两种问题，任意一种都会让演示失败：

| 问题 | 表现 | 出现过 |
|---|---|---|
| 厂家程序没起来或退出了（`linkhou_robot.service`，`Restart=no`，退出后不会自己重启） | ping、ssh 都正常，但激光、底盘状态、定位都没有数据；`gento relocate`、`gento goto` 报错 | 11-16、11-18 |
| 升降 / 腰部 / 头部的驱动器开机时没被手臂控制器初始化 | 读数全是 0，切换位置模式报 `-28 PDO data not init complete`；任务现在会按固定的示教值（升降 700 mm）继续，只用双臂；`gento doctor` 给出警告 | 11-12、11-13、11-20 |
| 底盘连 Orin 的网口 `eth1` 掉线 | 掉线时 ping 时通时断；任务报“导航桥状态超时”；厂家定位可能因为 IMU 超时被重置 | 11-17（9 分钟内掉了 39 次） |

`gento doctor` 一条命令能把这几种情况分开，并告诉你该怎么处理。它不会动车，约 30～40 秒。

底盘上还有一个**自动看护服务** `gento-vendor-watchdog`：厂家程序停了或开机没起来时，它会自动重启厂家服务、取消残留的导航任务，再自动重定位（先按 T、D 的位置匹配，不行就搜整张地图）。Orin 上的任务会**原地等它恢复**（最多 20 分钟，夹爪一直夹着），恢复后把被打断的那一段（去 D、倒车或回 T）重新执行，接着往下走。10 分钟内最多自动重启 3 次，再不行就要断电重启。记录在底盘 `~/gento_dock/watchdog.log`，`gento doctor` 也会显示重启过几次。

## 演示前（提前 30 分钟开始）

1. **先松开所有急停（包括上身的），再整机断电重启一次。** 开机后等满 **3 分钟**，让厂家程序启动完。急停按着开机，是升降 / 腰部 / 头部没被初始化的最可能原因。
2. **执行 `gento doctor`**，必须看到 `==== 总结论：可以开始 ====`。
   - 有 `[失败]` 时，按那一行箭头后面的提示处理，再执行一次 `gento doctor`。
   - `[警告]` 要看一下：例如“eth1 掉线 N 次”说明网口已经不稳，再断电重启一次。
3. 定位有问题时执行 `gento relocate`，然后再 `gento doctor`。
4. **完整演练一轮**：`gento task --handover`。跑完后看日志顶部：
   - 响应时间是否合格；
   - `chassis eth1 link changes during this run: 0`（掉线次数应为 0）。
5. 把车停回 T，准备好托盘。

## 演示期间

- 急停旁边一直要有人。网口掉线时，Orin 发出的软件停车指令到不了底盘。
- 不要在底盘上执行别的命令或诊断。底盘本来就很忙（4 核，负载 10～14）。
- 每两轮之间执行一次 `gento doctor`，大约 30 秒。

## 出问题时

| 看到的 | 怎么办 |
|---|---|
| 任务里出现“底盘程序停止或没有数据：原地等待底盘自动恢复后继续” | 不用操作，等 2～3 分钟，任务会自己接着走。盯住车 |
| “底盘自动恢复已放弃”，或体检显示“自动看护已放弃” | 只重启底盘（不要关 Orin，任务会继续等），开机后它会自动恢复，任务接着走；实在不行就 Ctrl-C，整机断电重启，`gento doctor`，重新跑 |
| “自动重定位没成功” | `gento relocate`（或在厂家网页上重定位）。定位对了，任务会自己继续 |
| 任务里出现“底盘导航桥 … 无状态”的警告 | 这时网口可能在掉线，任务会等最多 60 秒。**底盘作业会自己跑完**，网络恢复后任务会读到结果，继续往下走。盯住车，必要时拍急停 |
| “底盘失联：原地等待底盘自动恢复后继续” | 网络断了超过 60 秒，任务在等。网恢复后：作业还在跑就接着等它到站，已经失败就等底盘确认正常后重做这一段。盯住车，必要时拍急停 |
| “定位不对”“localisation looks wrong” | `gento relocate`，不行就在厂家网页上重定位 |
| “去 D 失败（…），自动重试 1/2” | 不用操作：底盘先停下，确认正常（定位有问题会先自动重定位），再把这一段重跑，最多重跑 2 次。倒车退出没完成会直接去 T |
| 任务最后还是失败了，或被 Ctrl-C / 断电停掉 | 处理完原因后 `gento task --resume`：托盘还夹着就直接去放置点，已经放好就直接回 T。停在放置动作中途的，用 `gento task --finish-place 135` |
| “被挡住，原地等待障碍物离开后自动继续” | 把障碍物拿开（比如传送带上留下的篮子），车会自己继续开，不用按键；要放弃就 Ctrl-C |

## 需要厂家处理或由你决定的

- 告诉厂家：我们加了自动看护，会在他们的程序停掉时执行 `systemctl restart linkhou_robot`；请他们说明为什么有时开机后 `linkhou_robot` 根本没启动（那几次日志里没有任何记录）。
- 把 `eth1` 掉线的问题报给厂家：内核 `6.1.158-rt58`，驱动 `hobot_gmac` 加 RTL8211F，日志里有 `gmac_check_tx_fifo: tx queue:0 fifo is not empty`。
- 厂家的 DDS 配置 `/etc/ros/cyclonedds/cyclonedds.xml` 绑定在 `eth1` 上。网口一掉线，底盘内部的 ROS 通信可能也会一起受影响，这一点请厂家确认。
- 可以试着关掉网卡的 TSO：`sudo ethtool -K eth1 tso off`，重启后会失效。是否这样做由你决定。
